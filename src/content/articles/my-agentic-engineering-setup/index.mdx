This is the concrete counterpart to [Agentic Engineering](/writing/agentic-engineering). That article describes the principles; this one records the tools and working habits I currently use to apply them. The setup will change as the harnesses and models improve.

## Planning work across sessions

For work that will outlive a single session, I sometimes use a [wayfinder](https://github.com/simonamtoft/claude-code-setup/blob/main/skills/wayfinder/SKILL.md) map to settle the consequential *what* and *why* before implementation starts. I use it selectively. Combined with `grill-me` or other planning skills, each answer can produce another branch of questions. Once the important decisions are clear, a short plan is enough.

For larger multi-session efforts, I use [Backlog.md](https://github.com/MrLesk/Backlog.md). Instead of asking plan mode for one monolithic implementation plan, I use it to refine durable tickets whose decisions, progress, and dependencies remain visible across sessions.

## Isolated execution with worktrees

Independent tickets can run in separate Git worktrees; dependent tickets remain sequential. Claude Code supports this through [`--worktree` sessions and worktree-isolated subagents](https://code.claude.com/docs/en/worktrees). For Pi, I built [pi-worktree-agents](https://github.com/simonamtoft/pi-worktree-agents) around the same model.

The point is not to maximise the number of tickets. It is to keep the backlog alive and consequential reasoning close to the code, where Git makes completed work searchable without introducing another system that can drift from the implementation.

## One setup across harnesses

My [Claude Code setup](https://github.com/simonamtoft/claude-code-setup) is public as a worked example. Its context files, hooks, and skills were added and removed in response to observed failure modes. Because they are plain files, I symlink the same artifacts into other harnesses such as [Pi](https://pi.dev/) instead of maintaining two copies.
